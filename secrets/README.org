#+title: Secrets

Secrets are managed with age encryption and integrated with nix using the wonderful [[https://github.com/ryantm/agenix?tab=readme-ov-file#ageidentitypaths][Agenix]] by ryantm.

* Declaring secrets

Every secret is declared beside what uses it, in the =site.nix= of its app or
module: an app's under =site.apps.<app>.secrets=, an OIDC client's through its
=auth.clients=, and anything belonging to no app under =site.secrets=.

#+begin_src nix
secrets = {
  mapbox-token = { kind = "credential"; description = "Mapbox access token, for TREK maps"; };
  session = { kind = "key"; generate = "rand"; };
};
#+end_src

A declaration's =kind= picks its directory; an app's file is named
=<app>-<name>= unless =file-name= says otherwise. =generate= says how
[[file:scripts/init-keys.sh][init-keys.sh]] makes a key, =optional= that its absence merely turns off what
uses it, and =recipients= narrows who may decrypt it from every host to those
named. Modules read the file from the declaration, e.g.
=config.site.apps.trek.secrets.mapbox-token.file=.

[[file:secrets.nix][secrets.nix]] derives agenix's rules from these declarations, by way of
[[file:../site/manifest.nix][site/manifest.nix]], so it is never edited by hand; [[file:recipients.nix][recipients.nix]] holds the
public keys secrets are encrypted to. A flake check fails on a declared secret
with no file, and on a file nothing declares.

* Layout

Secrets are grouped by what they are, not by which service reads them:

| Directory      | Contents                                                              |
|----------------+-----------------------------------------------------------------------|
| =oidc/=        | OIDC client secrets, each paired with its =*-hash.txt= digest         |
| =credentials/= | Anything that must be sourced or set by hand                          |
| =passwords/=   | Secrets we issue ourselves: admin passwords, tokens we mint           |
| =keys/=        | Key material a service signs or encrypts with, plus the Clevis blobs  |
| =scripts/=     | The generators, and =lib.sh= holding what they share                  |

[[file:make.sh][make.sh]] is the entry point. Run bare it creates whatever is absent;
=--list= shows the state of everything managed; naming a generator
(=make.sh <keys|wireguard|oidc>=) runs just that one, passing any further
arguments through. The scripts under =scripts/= can equally be run directly.

OIDC credentials are the exception to a bare run: they are made per client, by
naming it to [[file:scripts/make-oidc.sh][make-oidc.sh]].

The line between =credentials/= and =passwords/= is how the value comes to
exist. A credential has to be fetched or set manually: from a third party
(Fastmail, Bunny) or from a running service that alone can mint it
(=tailscale-preauth= from headscale, =ntfy-webpush-keys-env= from ntfy). Everything
in =passwords/= we can generate ourselves, at any time, from nothing, and a
person handles it at some point: it is typed into a login form, or pasted into
another service's settings (=llm-api-key=, =multi-scrobbler-endpoint-token=).

=keys/= is separate again: material only machines ever handle, whether a
service signs and encrypts its own data with it or one service presents it to
another with nobody typing it in between. It is generated by
[[file:scripts/init-keys.sh][init-keys.sh]], and must be held identical across every node that reads it.

* Editing Secrets

Any declared secret can be created or edited with agenix, which finds its
recipients in [[file:secrets.nix]]; declare it first.

#+begin_src shell
EDITOR=vim nix run github:ryantm/agenix -- -e credentials/hardcover-token.age
#+end_src

If you change ssh keys and need to re-encrypt your age secrets the following command will re-encrypt all of them.

#+begin_src shell
EDITOR=vim nix run github:ryantm/agenix -- -r
#+end_src

* Key material

[[file:scripts/init-keys.sh][init-keys.sh]] generates every declared key that does not already exist. It
never overwrites: these keys sign and
encrypt data that already exists, so replacing one is destructive. A fresh
=authelia-storage= leaves the encrypted Postgres columns unreadable, and a
fresh =lldap-key-seed= invalidates every key derived from it.

#+begin_src shell
./make.sh keys --list  # show what exists
./make.sh keys         # generate whatever is missing
#+end_src

To rotate a key deliberately, delete the file and re-run.

* Mesh keys

[[file:scripts/init-wireguard.sh][init-wireguard.sh]] generates a WireGuard keypair for any node that lacks one.
Unlike everything else in =keys/=, these are *not* shared: a node's private key
is its identity on the mesh, so each is encrypted to that host alone. The
matching =wg-<host>.pub= is committed in the clear and read at evaluation time
by [[file:../modules/wireguard-mesh.nix][wireguard-mesh.nix]].

#+begin_src shell
./make.sh wireguard --list  # show which nodes have keys
./make.sh wireguard         # generate whatever is missing
#+end_src

Commit the =.pub= files before deploying: a node cannot build until every peer's
public key is in the repository. Rotating a key means redeploying every node.

* Authelia secrets

The individual commands behind =init-keys.sh=, for reference.

The majority of Authelia secrets are just 64 character long random strings that can be easily generated.

#+begin_src shell
nix run 'nixpkgs#authelia' -- crypto rand --length 64 --charset alphanumeric
#+end_src

a notable exception is =authelia-oicd-issuer.pem= which is actually an RSA keypair.

#+begin_src shell
nix run 'nixpkgs#authelia' -- crypto pair rsa generate
#+end_src

Apparently Authelia does support DSA keys which could be interesting in future.

** OIDC secrets

Most often we want to create OIDC keys, consisting of an encrypted secret
(supplied to the application) and a hash (given to Authelia). We can get both at
once with:

#+begin_src shell
nix run 'nixpkgs#authelia' -- crypto hash generate argon2 --random --random.length 72 --random.charset rfc3986
#+end_src

The secret goes in =oidc/<client>-secret.age=, and the hash in
=oidc/<client>-hash.txt=, where =<client>= is the client's ID in its app's
=auth.clients=. [[file:scripts/make-oidc.sh][make-oidc.sh]] does both:

#+begin_src shell
./make.sh oidc headplane
#+end_src

* Environment files

A secret whose name ends in =env=, such as =credentials/mealie-credentials-env.age=,
is an environment file rather than a raw secret.

#+begin_example
OIDC_CLIENT_SECRET=<super secret value>
#+end_example
